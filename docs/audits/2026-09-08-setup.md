# Setup backend implementation — 2026-09-08

Implemented locally; no live Home Assistant access, deployment, hardware command, or commit.

## Contract

Admin-only response services `crop_steering.setup_read`, `setup_create`, `setup_save`, and `setup_remove` are discoverable through the HA service registry. HTTP consumers call `/api/services/crop_steering/<service>?return_response` and read `service_response`. Read returns API version 1, capabilities, all room configurations (including archived rooms), safety blockers, and searchable HA entity candidates. Example: [setup-fixture.json](2026-09-08-setup-fixture.json).

Create submits `{room_name,zones,hardware}` through the native HA config-entry flow. Save submits `{entry_id,expected_revision,room_name,active,zones,hardware}`. Archive submits `{entry_id,expected_revision,confirm_name}`; the exact selected room name is required. Restore uses save with `active:true`. Native manual configuration remains supported and is now the recommended initial method.

Every allocated zone ID stays stable. Removal archives a slot; later IDs are never renumbered and entries are never destroyed by setup services. Include archived slots on save; append at the next ID. Maximum 24 allocated slots. Existing entry/entity identities, unrelated options, zone metadata and controller counters are preserved. Named `default` is reserved for new additional rooms because existing controller state uses that key for the prefix-free room.

## Validation and lifecycle

All setup changes require affected engine controls and the union of old/new valves, pump, mainline and waste hardware to read exactly OFF. Shared plumbing expands this check transitively across rooms. Missing/unavailable states fail closed. Creation may lack its not-yet-created engine entity, but checks any existing flag and mapped hardware. No setup service activates hardware.

Only existing entities of supported domains can be mapped. VWC accepts percent, EC accepts mS/cm or dS/m, and feed pH accepts pH or no unit. Duplicate active valve allocations and valve/shared-hardware role collisions are rejected across rooms. Existing archived probes can remain referenced when their physical entities have been removed. Sizing limits: 1–1000 plants; 0.1–200 L substrate; 1–20 drippers; 0.1–50 L/h per dripper. Entity IDs and units are validated on the server, independently of the picker.

Configuration changes increment setup_revision. The descriptor publishes revision, active room status, active zone IDs and labels. Save success confirms persisted configuration; the frontend must wait for controller heartbeat revision acknowledgement before treating the mapping as applied. The controller agent owns that reconciliation and its independent validation.

Fresh manual/API default rooms receive a dedicated engine switch, initially OFF. Existing default entries keep the legacy input_boolean flag. The descriptor carries the exact override so the controller can apply its safe migration rules.

## Installation

The integration serves its bundled `www/dashboard.html` at `/crop_steering/dashboard.html` and registers an iframe sidebar at `/crop-steering`. Static registration runs once; existing user panels are preserved; only this integration's panel is removed when its final room unloads. Manifest dependencies include frontend and http. Current HA uses async static registration; HA 2024.3 uses the available legacy method.

API choices checked against primary HA sources: [static-path migration](https://developers.home-assistant.io/blog/2024/06/18/async_register_static_paths/), [response services](https://developers.home-assistant.io/docs/dev_101_services/), and [native iframe registration](https://raw.githubusercontent.com/home-assistant/core/2024.3.0/homeassistant/components/panel_iframe/__init__.py).
