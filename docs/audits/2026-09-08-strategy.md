# Continuous grow strategy implementation audit — 2026-09-08

Status: locally implemented and tested. No production Home Assistant access, hardware operation, deployment, or commits were performed.

## Implemented contract

The integration owns a version 1 document in HA Store `crop_steering_strategy_<config_entry_id>`. Room identity is canonical and exact: `room:` for the unprefixed room, `room:f1_` for the `f1_` descriptor. The strategy API never guesses a room or calls legacy cross-room recipe services.

Five response-only `crop_steering` services are registered:

| Service | Inputs | Response |
| --- | --- | --- |
| `strategy_get` | `room_id` | Current document, catalog and capability |
| `strategy_save` | `room_id`, `plan`, `expected_revision` | Saved draft with incremented revision |
| `strategy_preview` | `room_id`, optional `plan`, optional `date` (`YYYY-MM-DD`) | Current document plus `preview: {date, zones}` |
| `strategy_activate` | `room_id`, `expected_revision` | Explicitly armed document and `armed_after` |
| `strategy_disarm` | `room_id` | Disarming document and durable `disarm_after`, or draft when no active plan exists |

The common response contains `room_id`, `revision`, `status`, `plan`, `active: {grow_day, zones}`, `error`, `catalog`, `capabilities: {strategy_snapshot_version: 1, controller_supported}`, `armed_after`, `disarm_after`, and `disarm_policy`. Preview zone rows contain `zone_id`, `day`, `status`, `profile_id`, `bias`, `parameters`, `hydraulics`, and `errors`. Status values are draft, armed, active, disarming, or error. Preview zone status is waiting, active, or complete.

A plan has `schema_version: 1`, `profiles: [{id, name, vegetative, generative}]`, and `zones: [{zone_id, start_date, schedule: [{start_day, end_day, profile_id, bias}]}]`. Day 1 is the zone start date. Weekly inputs `start_week/end_week` normalize to exact inclusive daily ranges. Schedules must begin on day 1 and remain contiguous without overlap, with at most 366 days. Every active setup zone must appear exactly once; foreign, duplicate, and archived IDs are rejected. New/removed setup zones require explicit draft reconciliation, never automatic persistent plan mutation.

Profiles supply both endpoint dictionaries with matching keys. Required canonical parameters are dryback_target, ec_target_p0/p1/p2, p1_target_vwc, p2_vwc_threshold, p2_shot_size, p1_initial_shot_size, p3_emergency_vwc_threshold, and p3_emergency_shot_size. Additional supported fields are p1_shot_size_increment, p1_maximum_shots, p1_time_between_shots, p0_maximum_wait_time, max_daily_volume, field_capacity, maximum_ec, and watchdog_hours. Unsupported/inert intelligence parameters and legacy recipe-stage selection are excluded.

## Continuous execution and bounds

Each parameter is `vegetative + (generative - vegetative) * bias / 100`, with bias 0 through 100. The result rounds to the catalog native step with ties toward positive infinity, matching JavaScript Math.round; final setpoints round to six decimals using the same tie direction. Integer shot counts stay integral. Bounds are the intersection of readable HA number limits, both native mode families where relevant, and the controller's actual validate_params limits. A regression reads the canonical core _PARAM_BOUNDS to prevent catalog drift. Endpoint step alignment and VWC/EC relational rules are checked before saving and again for interpolated schedule values.

Both native vegetative/generative dryback reads and both veg/gen EC phase reads resolve to the same canonical active snapshot values. Legacy select mode therefore cannot bypass the slider. Existing legacy mode entities and parameter ranges remain available when no strategy is active. The starter plan copies currently readable values into identical endpoints and labels them "configure endpoints". Missing required values are not fabricated. No pot-size-based agronomic setpoints are introduced.

Dryback is relative percent of detected peak, as actually implemented by controller `_snapshot`: `(peak - vwc) / peak * 100`. Thus peak 60 and target 10 means 54 VWC, not 50. Earlier repository descriptions of this field as percentage points were incorrect. The preview helper regression preserves this existing engine semantics.

The predictive P2-to-P3 calculation previously divided relative dryback percent by a VWC-percentage-point/hour rate. It now computes target VWC from detected peak, subtracts that target from current VWC, and divides the remaining VWC points by the measured rate. Peak60/current 60/target 10/rate 1 needs 6 hours; current 57 needs 3 hours. Canonical and vendored core.py were updated together. The existing early-P3 edge fixture now explicitly supplies peak 60 and rate 2, so 55 to 48 requires 3.5 hours rather than relying on the old mixed-unit arithmetic.

## Lifecycle and failure behavior

Saving requires a matching document revision and draft status. Activation requires readable room configuration, fresh VWC/EC, valid positive hydraulic sizing, and a recent heartbeat declaring strategy_snapshot_version 1. Persistence must succeed before arming. Hardware enable flags are never enabled by these services.

An armed plan applies at the next local lights-on boundary, observed within a 120-second window. It never catches up by applying a missed boundary midday. Each active snapshot has a 180-second lease. Restarted stale-day plans hold until a future eligible boundary. Corrupt storage cannot arm seeded defaults. Saving or arming without durable storage fails.

Disarm records a separate durable next-boundary target. It keeps the current effective setpoints until that boundary, then explicitly releases to legacy control. A request within the current boundary window cannot release immediately. A missed disarm boundary or restart preserves the disarm intention and cannot reactivate the plan. Disarm does not toggle engine or hardware flags; an operator requiring an immediate stop uses the engine disarm control.

The integration publishes one coherent `sensor.crop_steering_<prefix>strategy_plan` snapshot. The controller persists whether strategy execution is required, validates room/version/lease/completeness, and holds when an activated snapshot disappears or becomes invalid. A fresh draft release is required to clear that durable requirement. Before each future shot the controller refreshes the snapshot. Any changed, released, stale, or held snapshot invalidates the entire pending decision batch until the next loop rebuilds it, including later zones after a long first shot. Existing in-flight kill-switch and hardware fault behavior remains in force.

Setup changes require all current/requested engine flags and old/new mapped hardware explicitly OFF before descriptor adoption. Startup reconciles lifecycle descriptors before the first control pass, so archived rooms/default zones cannot run for the former 300-second rediscovery delay. Zone IDs remain stable and archived zone counters survive. Active strategy/setup zone mismatches hold the room, including newly added zones; the catalog recomputes from current setup on each response/preview.

New explicit default-room setups can use native `switch.crop_steering_engine_enabled` while legacy/custom readable flags retain precedence. Per-zone pot volume, emitter count, emitter flow and plant count are consumed without replacing absent legacy sizing overrides. Setup sizing applies once per changed configured value/revision; unrelated setup changes preserve later HA tuning. The integration now exposes the existing 900-second max_shot_duration default as a 5..3600-second number so fresh-install previews have a readable cap.

## Hydraulic units and runtime parity

Zone substrate liters = pot liters per plant × plant count. Zone flow liters/second = plant count × emitters per plant × emitter liters/hour ÷3600. Shot liters = zone substrate × shot percent ÷100. Raw seconds = shot liters ÷ actual positive flow. Preview reports raw volume/duration and effective capped whole seconds; runtime uses the same actual flow, a 5-second minimum, and the configured explicit maximum duration.

Example: 36 plants × 6 L, one 4 L/hour emitter each, 6% initial shot => 216 L substrate, 0.04 L/s flow, 12.96 L shot, 324 seconds. Low-flow regression: one 6 L pot, one 2 L/hour emitter, 6% => 0.36 L and 648 seconds. The former runtime 0.001 L/s denominator floor incorrectly shortened that low-flow case to 360 seconds and was removed. Explicit zero/negative/nonfinite emitter sizing is rejected rather than silently substituting the legacy fallback; missing legacy sizing retains its existing option fallback. Hydraulic preview is a deterministic baseline, not a forecast of transpiration, adaptive EC corrections, future sensor readings, or final crop response.
